The flow, end to end

There is no redirect to a hosted checkout and no merchant gateway in the middle. The buyer pays your account directly; paisabridge proves the payment happened and keeps the ledger straight.

What makes it different

Signed, not parsed

A webhook is accepted only after its signature verifies. An unsigned e-mail or SMS alert can open a review, never a delivery — so a forged credit alert cannot ship goods.

No typing, no collisions

Each order owns a distinct amount inside a ±Rs 9 band, so a payment matches by amount alone. Two open orders can never share one.

Idempotent everywhere

Replayed webhooks, duplicated wallet top-ups and retried order creates all collapse to one effect. The ledger is append-only and keyed.

An operator console, not a curl script

The bank rail deliberately parks payments in a review queue, because an alert anyone can e-mail is not proof. That queue is a real screen: one click approves, one click rejects, and every decision is appended to the order journal.

Install in one line

go install github.com/horizonbymuneeb/paisabridge/cmd/paisabridge@v0.1.0

Needs Go 1.22+ and a C toolchain (the SQLite driver uses cgo).

Then set an admin token and one rail secret, and the gateway is live: 

export PB_ADMIN_TOKEN="$(openssl rand -hex 24)"
export PB_BANK_RELAY_SECRET="$(openssl rand -hex 32)"
export PB_PUBLIC_URL=http://localhost:8080
./paisabridge
