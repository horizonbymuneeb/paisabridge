Getting started

Fifteen minutes from a clean machine to a fulfilled order, using the bank rail so no provider onboarding is needed.

1. Install

go install github.com/horizonbymuneeb/paisabridge/cmd/paisabridge@v0.1.0

Or from source:

git clone https://github.com/horizonbymuneeb/paisabridge
cd paisabridge
make build          # CGO_ENABLED=1 go build ./cmd/paisabridge

Go 1.22+ and a C toolchain (the SQLite driver uses cgo; on Debian: apt install build-essential).

2. Configure

export PB_DB=./paisabridge.db
export PB_ADMIN_TOKEN="$(openssl rand -hex 24)"
export PB_BANK_RELAY_SECRET="$(openssl rand -hex 32)"
export PB_PUBLIC_URL=http://localhost:8080
export PB_ADMIN_ADDR=127.0.0.1:8081     # operator console, separate listener
./paisabridge

Expected log:

level=INFO msg="database ready" path=./paisabridge.db
level=INFO msg="rail easypaisa disabled: EasypaisaSecret not set"
level=INFO msg="rail jazzcash disabled: JazzCashSalt not set"
level=INFO msg="listening" addr=:8080 dev_mode=false methods=bank
level=INFO msg="admin console listening" addr=127.0.0.1:8081
Rails you did not configure are skipped

A rail with no secret is simply not offered, and its webhook answers no_adapter. Booting does not depend on configuring rails you do not sell.

3. Create an order

curl -s -X POST localhost:8080/api/orders \
  -H 'content-type: application/json' \
  -d '{"product_id":"chatgpt-plus","product_name":"ChatGPT Plus 1m",
       "catalog_price_minor":149900,"currency":"PKR","method":"bank"}'
{
  "id": "ord_eb5f4d39f0ab410dc4",
  "ref": "ref_661a75903e39870351",
  "catalog_price_minor": 149900,
  "amount_minor": 150700,
  "currency": "PKR",
  "method": "bank",
  "status": "pending_payment",
  "expires_at": "2026-10-31T08:45:00Z"
}
The buyer sends amount_minor, not the list price

The two differ by a bounded offset of at most Rs 9, in either direction. That offset is what makes the payment identifiable without the buyer typing a reference. Always show the payable amount in your checkout UI.

4. Verify a payment

go build -o pbsend ./cmd/pbsend

./pbsend -url http://localhost:8080/api/webhooks/bank \
         -secret "$PB_BANK_RELAY_SECRET" -method bank \
         -amount 150700 -txn IBFT-001 \
         -note "Rs 1507.00 has been credited to A/C 12345678901234 from Ali Raza"
HTTP 200
{"matched":true,"order_id":"ord_eb5f4d39f0ab410dc4","reason":"matched","credited":true}

The order is now fulfilled. Re-send the same notice and it is refused:

HTTP 401
{"error":"invalid_signature","detail":"... notice: replayed envelope id"}

5. Tell your storefront

Pick one of three channels; most deployments use the webhook plus the bot.

ChannelSetup
PollGET /api/orders/{id}
Outbound webhookPB_OUTBOUND_WEBHOOK_URL + PB_OUTBOUND_SECRET
Telegram botPB_TELEGRAM_TOKEN; buyers use /order <ref>

Wallet payments

A wallet top-up settles instantly and earns the prepay discount (5% by default).

curl -X POST localhost:8080/api/wallet/topup -H 'content-type: application/json' \
  -d '{"user_id":"tg:123456789","amount_minor":500000,"idempotency_key":"topup-1"}'

curl -X POST localhost:8080/api/orders/ord_.../claim \
  -H 'content-type: application/json' -d '{"user_id":"tg:123456789"}'
{"order":{...},"price_minor":150000,"discount_minor":7500,"charged_minor":142500}
